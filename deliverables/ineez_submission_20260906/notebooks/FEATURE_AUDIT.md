# 변수 설계의 네 가지 질문: 공통 입력 통제 실험

## 목적

Ridge 중심의 초기 변수 탐색이 비교 결과를 유리하게 만들었는지, 수급 성분의 조건부 가치와 반응 시차, 동일 가중치 압축의 영향을 검사한다. 기존 결과로 동기가 생긴 **회고적 추가 탐색**이며 새 최종 홀드아웃을 확보한 실험이 아니다.

## 공통 조건

- 모델: Ridge·ElasticNet·LightGBM·CatBoost. `src/ml_experiment.py:pipeline_for`의 고정 설정을 재사용한다.
- 13개 입력 조건 × 4개 모델 × H1/H2/H3를 비교한다. 모델별로 선호하는 입력을 미리 다르게 주지 않는다.
- 모든 모델은 horizon별 로그 수익률을 학습하고 현재 가격 × exp(예측 수익률)로 가격을 복원한다.
- 학습 구간에서만 중앙값 대체(결측 지시자 포함)와 표준화를 적합한다. ‘원시값’은 전처리 없이 넣는다는 뜻이 아니라 경제적 변환 전 수준값이라는 뜻이다.
- 생산·소비는 기준월 대비 2개월, 재고 1개월, 시장 0개월의 기존 보수적 가용성 가정을 유지한다. 실제 공표 빈티지·개정 데이터의 완전한 재현을 의미하지 않는다.
- 각 원점의 학습 타깃은 j+h≤t를 만족한다. 내부 예측 캐시는 72번 원점부터, 외부 평가는 120번 원점부터다.
- 외부 평가 원점은 H1/H2/H3 83/82/81개로 고정한다. MAPE가 주 지표이고 MAE·방향·반전 F1도 저장한다.
- 기존 모델과 입력 변경의 효과를 분리하기 위해 CPU 및 기존 모델 설정을 유지한다. 앞서 수행한 GPU Chronos나 DL을 재학습하는 작업은 아니다.

## 1. 특정 모델에 유리한 표현인가?

| 이름 | 가격 특징 | 수급·시장 특징 |
|---|---|---|
| basic_raw | 현재·1·2·3·6·12개월 가격 + 월 sin/cos (8개) | 생산·재고·소비·BCOMNG 수준 |
| basic_processed | 위 기본 특징 | 생산 수준·계절 재고 Z·소비 Z·BCOMNG 수익률 |
| engineered_raw | 기존 가격 시차·수익률·이동통계·월 특징 (18개) | 원시 수준 4개 |
| current | 기존 가격 특징 | 현재 가공 특징 4개; 이전 D_market과 동일 |

가격 특징과 외생 특징 표현을 2×2로 나누어 어느 변화에서 개선되는지 확인한다. 기본과 가공 가격 특징의 수는 다르므로 모델별 표현 선호의 진단이지 차원·정보량까지 고정한 실험은 아니다. 외생변수의 추가 시차 확장이나 모델별 하이퍼파라미터 최적화는 이 질문에 포함하지 않는다.

## 2. 생산·재고·소비 각각이 도움이 되는가?

current에서 `production_level`, `storage_seasonal_z`, `consumption_z`를 각각 하나씩 제거하고 다시 학습한다. 시장 의존도를 확인하기 위해 `BCOMNG_INDX_return` 제거도 포함한다. 다른 특징과 가용성은 유지한다.

오차가 증가하면 현재 다른 입력이 있는 상태에서 추가 예측 가치가 있었다는 근거다. 오차가 줄면 현재 표현·설정에서 중복·잡음 가능성을 의심한다. 원시 변수의 모든 대리 신호를 없애는 실험이나 인과효과 추정이 아니다.

## 3. 경제적 반응 시차를 잘못 잡았는가?

current의 수급 세 특징에 **공통 추가 시차 0·1·3·6개월**을 적용한다. 예를 들어 생산의 추가 시차 3개월은 원시 기준월 대비 총 5개월 지연이다. 시장 수익률과 가격 특징은 그대로 둔다.

매 외부 원점에서 정답이 확인된 최근 36개 과거 원점(최소 24개)의 MAPE로 네 시차 중 하나를 선택한다. 과거 예측 역시 그 당시 가용 정보로 학습한 결과다. 시차 선택 풀에는 Naive를 넣지 않고 별도 기준선으로만 비교한다. 선택 점수와 마지막 정답 시점을 모두 저장한다.

이 실험은 수급 세 성분이 함께 더 늦게 반응하는지에 대한 제한된 진단이다. 성분별로 서로 다른 시차를 조합하거나 여러 시차를 동시에 입력하는 실험은 아니다. 고정 시차의 사후 최저 성적과 과거 기반 선택 절차 성적을 구분한다.

## 4. 합성 수식이 정보를 잃는가?

- individual_z: 기존 가격 특징 + 생산 Z·재고 Z·소비 Z + BCOMNG 수익률.
- equal_index: 같은 가격·시장 특징 + (생산 Z + 재고 Z − 소비 Z).

양쪽의 세 Z값과 발표 지연은 동일하다. current의 혼합 표현을 그대로 더하지 않는다. 생산·재고·소비를 세 개에서 하나로 바꾸는 것 외의 입력은 유지한다. 이 지수는 공급 압력의 후보이지 가격과 단위가 같은 회계식이 아니며 지수와 수익률의 부호를 강제로 고정하지 않는다.

성능 차이에는 독립 정보 압축뿐 아니라 차원 감소와 규제 효과의 변화도 포함된다. 특히 Ridge에서 동일 가중치 압축은 각 변수의 독립 계수를 제한하는 효과가 있다.

## 출력과 재현

```powershell
uv run --extra dev --extra dl --extra chronos python -m pytest -q -p no:cacheprovider
uv run --extra dl --extra chronos python -m src.feature_audit
uv run --extra dl --extra chronos python -m src.feature_audit_report
```

`outputs_feature_audit/`에 입력 명세·실제 계산 특징·예측·연도별 지표·쌍별 차이·과거 시차 선택 기록을 저장한다. `cache/`는 같은 코드·데이터·환경·설정일 때만 재사용한다. 설정이 달라지면 기존 결과를 덮어쓰지 않고 중단한다.

`contrasts.csv`의 `delta_mape_pp`는 후보−참조다. 음수는 후보 개선, 양수는 후보 악화다. 제거 실험의 양수는 해당 변수를 유지하는 쪽이 좋았다는 뜻이다. 승리한 연도·원점 수는 유의성 검정이 아니다.

최상위 결과를 자동으로 최종 모델에 반영하지 않는다. 새 후보를 선택하면 추가 안정성 검증과 보고서 정합성 확인이 필요하며 `submission.csv`는 유지한다.
