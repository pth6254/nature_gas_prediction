# 가설·특징·조합 실험 읽는 방법

후보 목록과 실험 결과는 최종 설계 확정이 아닙니다. 원래 `submission.csv`와 모델 선택에는 반영하지 않습니다.

## 재현

프로젝트 루트에서 다음 명령을 실행합니다.

```powershell
uv sync --extra dev
uv run python -m src.run_hypotheses
```

`src/hypotheses.py`는 원자료 열, 변환 수식, 발표 지연, 후보 조합과 비교할 부모 조합을 정의합니다.
`src/run_hypotheses.py`는 같은 H1/H2/H3 원점에서 전처리와 모델을 다시 학습하고 비교합니다.

## 무엇을 비교하는가

- `history`: 가격 이력만 사용하는 Ridge와 Last Value Naive 비교.
- `core_z`: 가격 이력 + 생산·저장·소비 각각의 누적 Z값.
- `production_*`, `storage_*`, `consumption_*`: 다른 특징을 고정하고 한 요소만 수준·월별 변화·YoY·계절 Z값으로 교체.
- `without_*`: 한 요소를 제거한 뒤 재학습. 단순히 기존 예측에서 기여도를 빼지 않습니다.
- `equal_index`: 같은 세 Z값을 생산+저장-소비로 합쳐 입력. 지수 계수 자체는 자유롭게 학습하므로 경제적 부호 제약 모델은 아닙니다.
- `signed_core`: `core_z`와 동일한 입력·L2 규제에서 생산·저장 계수는 0 이하, 소비 계수는 0 이상으로 제한. 가격 이력·절편·결측 지표는 부호를 제한하지 않습니다.
- `plus_imports`, `plus_canada`: 총수입 추가, 그 위에 캐나다 수입 추가. 캐나다 수입은 총수입과 중복될 수 있습니다.
- `plus_rigs_0/3/6`: 각 후보를 동일한 `core_z`에 추가하며 다른 추가 변수는 섞지 않습니다.
- `plus_<시장명>`, `plus_energy`: 시장 수익률을 개별 또는 함께 추가.
- `plus_weather`: 기온의 계절편차를 추가. 단위 확인 전 65도 기준 수요 proxy는 사용하지 않습니다.
- `seasonal_core`: 세 요소 모두 계절 Z값으로 교체하는 별도 조합.
- `plus_interaction`: `seasonal_core`에 소비 초과 × 저장 부족을 추가.

## 계산과 검증의 가정

누적 Z값은 최소 12개 관측에서 현재까지의 평균·표준편차로 계산합니다.
계절 Z값은 해당 관측을 제외한 **과거 동일 기준월** 관측을 최소 3개 요구합니다.
전체 과거 동일월을 사용하며 이동 3년/5년 같은 기간 탐색은 하지 않습니다.
생산량처럼 추세가 있는 변수의 과거 동일월 기준은 구조 변화에 뒤처질 수 있으므로 YoY 대안과 비교합니다.
월별 변화는 차분, YoY는 12개월 비율 변화, 시장 수익률은 1개월 비율 변화입니다.
변환 후 발표 지연만큼 이동하고 과거 값으로만 forward-fill합니다. 남은 결측은 각 학습 구간 중앙값과 결측 지표로 처리합니다.
모델 직전 표준화도 매 학습 구간 안에서만 적합합니다. 합성 지수와 개별 Z값도 이 단계에서 다시 표준화됩니다.

가용성 지연은 기존 프로젝트의 가정이며 실제 vintage 보장은 아닙니다.
모든 후보는 동일한 Ridge log-return, alpha=10을 사용합니다. 부호 제한도 같은 L2 목적함수이며 절편은 규제하지 않습니다.
결측 지표의 기여와 변수 간 상관이 있으므로 부호 제한이 시장 전체의 인과관계를 보장하지 않습니다.
계수 파일의 계수는 각 fold 표준화 이후 공간의 값입니다. fold 간 원자료 단위의 민감도로 직접 비교하지 않습니다.

각 horizon 안에서는 후보와 Naive의 검증 날짜가 같습니다. 마지막 미래 정답의 가용성 때문에 H1/H2/H3 표본수는 다릅니다.
모든 실험은 train 파일만 읽으며 test 파일을 읽지 않습니다. 학습 정답은 원점까지 관측된 값으로 제한합니다.
변수·수식 탐색용 비교이며 중첩 검증, 독립 최종 평가, 자동 변수 채택은 아직 포함하지 않습니다.
많은 후보 중 최고 성능을 최종 성능으로 주장하지 않고 이후 별도 선택 절차를 검증해야 합니다.

## 결과와 보고서 연결

`outputs_hypotheses/`에 다음 파일이 생성됩니다.

| 파일 | 보고서에서 답하는 질문 |
|---|---|
| `manifest.json` | 어떤 가설·입력·비교군·고정 설정으로 실험했는가? 입력 파일 SHA-256 포함 |
| `feature_definitions.csv` | 어떤 원자료에 어떤 계산과 지연을 적용했는가? |
| `feature_values.csv` | 실제 날짜별 변환 값은 무엇인가? |
| `predictions.csv` | 원점별 실제·예측·현재·직전 가격은 무엇인가? |
| `metrics.csv` | 전체·연도별 MAPE, MAE, 방향·반전 성능은 어떠한가? |
| `comparisons.csv` | 부모 조합 대비 개선폭과 개선 연도 수는 얼마인가? |
| `coefficients.csv` | 원점별 모델 계수는 무엇인가? |

`delta_mape_pp < 0`이면 부모 조합보다 MAPE가 감소한 것입니다. 상대 개선율이 아닌 퍼센트포인트 차이입니다.
`delta_turning_f1_pp > 0`이면 반전 F1이 높아진 것입니다. 연도별 표본수는 `metrics.csv`에서 확인합니다.
부모 대비 개선과 Naive 대비 개선은 다릅니다. 보고서에서는 두 비교를 함께 확인하세요.
